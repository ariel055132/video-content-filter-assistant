## 一句話總結

Kyle 以企業 AI 開發與「32 歲不當受僱工程師」計畫，提出兩個互補問題：如何用 spec、harness 與 on-call agent 放大產出，以及如何在 AI 抽走 coding 工藝感、提高認知負荷時重建第二曲線。

## 核心重點

- 公司從 Copilot／Cursor 收斂到共同 agent 生態，並推動 spec-driven development：問題先修 spec，再重跑實作，而非直接手改生成碼。
- 通用 agent 很難一次做好；針對 UI migration 或 on-call 排障等特定場景，打通 K8s、日誌、文件與權限後，agent 可找到 root cause。
- AI 加速 coding 不等於整體流程等倍加速，review、資源申請與人際溝通仍是瓶頸；組織期待過高會增加壓力。
- 多 agent 迫使頻繁 context switching，產生「AI brain fry」式疲勞；需要限制非必要決策、安排恢復時間並檢查 token 是否轉成真實價值。
- 工程師應從「怎麼做」往「為什麼值得做」移動；Kyle 以自由、影響力、人生體驗為核心價值，探索社群經理、跨域 Product Builder 與深度生活。
